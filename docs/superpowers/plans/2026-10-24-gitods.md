# GitODS 实施计划

> **面向 Claude Code / AI 工作者：** 按本计划逐任务实施并用复选框记录进度。如果环境已安装 superpowers，可使用 subagent-driven-development 或 executing-plans；没有这些技能时直接执行本计划，不把安装技能作为阻塞条件。

**目标：** 上线一个采用 Gitee 风格的公开项目展示站，管理员管理自由分组、项目和实际独立分支，访客浏览与下载目录、源码及 README。

**架构：** Python/Django 单体，PostgreSQL 保存元数据与会话，本地私有持久目录保存不可变文件对象。Django 模板、定制 CSS 和 HTMX 完成前端，Django Admin 承担管理表单，生产不需要 Node。

**技术栈：** Python 3.13、Django 5.2 LTS 最新兼容安全补丁、PostgreSQL 17、Gunicorn、WhiteNoise、psycopg、django-environ、Pygments、markdown-it-py、nh3、Pillow、HTMX。测试使用 pytest、pytest-django、pytest-playwright。

**规格依据：** [设计文档](../specs/2026-10-24-gitods-design.md)。日期 2026-10-24。分支保留；不做 PR、提交历史或 Git 服务；不能替换成 SQLite。

- 当前目录仅有交付文档和参考图，没有应用、依赖环境或 Git 仓库。实现时再初始化项目，不假定已经存在 Next.js 或其他工程。

## 2. 固定服务契约

以下是服务接口约束，实施者补齐方法体；跨任务调用保持命名一致。`expected_revision` 是已读取的当前值，所有内容变更成功后递增。

复制隔离的核心测试形态：

```python
@pytest.mark.django_db
def test_branch_copy_has_independent_entries(project, branch):
    blob = Blob.objects.create(sha256="a" * 64, size=9)
    Entry.objects.create(branch=branch, path="README.md", parent_path="", name="README.md",
                         kind="file", blob=blob, size=blob.size)
    copied = create_branch(project_id=project.id, name="release-1.0",
                           source_branch_id=branch.id, expected_revision=branch.revision)
    origin = Entry.objects.get(branch=branch, path="README.md")
    clone = Entry.objects.get(branch=copied, path="README.md")
    assert origin.id != clone.id
    assert origin.blob_id == clone.blob_id
    clone.delete()
    assert Entry.objects.filter(branch=branch, path="README.md").exists()
```

上例仅使用隔离测试数据库中的 Blob 元数据，不读取尚未实现的物理对象；任务 5 接入对象存储，任务 6 还必须通过真实上传服务验证内容更新隔离，不能只靠直接 ORM 删除的测试。
